
# 피지컬 인공지능 응용

## 개요

> **풀고 싶은 문제**
> 같은 머신러닝 기본 틀을 여러 센서에 적용하면, TiCLE Lite를 단순 실습 보드가 아니라 상황을 해석하고 반응하는 피지컬 인공지능 장치로 바꿀 수 있을까?

### 학습 목표

- 9장의 수집 -> PC 학습 -> 보드 배포 파이프라인을 VR,CdS, 초음파, 디지털 마이크에 확장 적용할 수 있다.
- 대표점 비교 프로토타입과 Random Forest 배포 모델의 차이를 설명하고, 각각의 장단점을 비교할 수 있다.
- emlearn_trees로 학습된 Random Forest 모델을 보드에 배포하고 실시간 추론을 수행할 수 있다.
- 분류 결과를 Matrix, Servo, TextLCD, Audio 같은 출력 장치와 연결해 피지컬 피드백 루프를 설계할 수 있다.
- IMU 제스처 인식 결과를 새로운 출력 경험으로 확장할 수 있다.

### 이 장의 의미

이제부터는 9장에서 만든 기본 구조를 센서 종류별로 확장한다. 각 절은 보드에서 데이터를 수집하고, PC에서 모델을 학습한 뒤, 학습된 모델만 다시 보드에 올려 추론만 수행하는 세 단계로 일관되게 구성한다. 수집 파일은 보드에서 데이터를 모으고, PC 학습 파일은 모델을 만들며, 배포 파일은 보드에서 예측만 수행한다.

중요한 점은 센서가 달라도 프로그램의 큰 뼈대는 비슷하다는 것이다. 일정 시간 창으로 데이터를 모으고, 작은 특징 벡터로 압축하고, 분류 결과를 Matrix, Servo, TextLCD, Audio 같은 장치로 피드백을 준다. 각 절에서는 먼저 대표점 몇 개만으로 즉시 동작을 확인하는 프로토타입 버전을 살펴보고, 이후 PC에서 Random Forest를 학습해 emlearn_trees로 배포하는 버전으로 확장한다. IMU는 9장에서 이미 전체 파이프라인을 다뤘으므로, 이 절에서는 같은 모델 위에 새로운 출력 경험을 붙이는 응용 확장에 집중한다.

### 실습 구성

| 절 | 입력 센서 | 알고리즘 | 목표 |
|---|---|---|---|
| VR, CdS: 스마트 조명 | VR + CdS | 대표점 비교 / Random Forest | 맥락(의도+환경) 기반 조명 모드 분류 |
| 초음파: 비접촉 버튼 | 초음파 거리 | 대표점 비교 / Random Forest | 손짓 패턴으로 조작하는 비접촉 버튼 |
| IMU: 반응형 미니 펫 | IMU 가속도,자이로 | kNN (9장 모델 재사용) | 제스처 분류를 소리,색,서보 피드백으로 확장 |
| 디지털 마이크: 응원 반응기 | 마이크 RMS | 대표점 비교 / Random Forest | 음량,박수,조용함을 구분하는 소리 반응기 |

## VR, CdS: 의도와 환경을 함께 읽는 스마트 조명

> **풀고 싶은 문제**
> 사용자의 의도(VR)와 주변 밝기(CdS)를 함께 고려하는 조명을 만들고 싶다. 두 센서를 2차원 벡터로 묶으면 맥락에 따라 다른 조명 모드를 정확하게 선택할 수 있을까?

VR과 CdS는 각각 사용자 의도와 주변 환경이라는 서로 다른 정보를 담는다. 두 값을 2차원 벡터로 조합하면 같은 VR 위치에서도 주변 밝기에 따라 다른 상태로 구분할 수 있다. 이 절에서는 보드에서 데이터를 수집하고, 대표점 세 개로 즉시 분류하는 프로토타입을 확인한 뒤, PC에서 Random Forest를 학습해 보드에 배포하는 전 과정을 순서대로 진행한다.

### 데이터 수집

> **이 예제로 풀 문제**
> VR(가변저항)의 사용자 입력과 CdS의 환경 밝기를 동시에 기록해, 사용자 의도와 맥락을 함께 나타내는 데이터셋을 만들고 싶다. 두 센서의 값을 2차원 벡터로 조합하면 어떤 패턴이 나타날까?

VR과 CdS는 각각 사용자 의도와 주변 환경이라는 서로 다른 정보를 담는다. 두 값을 2차원 벡터로 조합하면 같은 VR 위치에서도 주변 밝기에 따라 다른 상태로 구분할 수 있다. 아래 예제는 night, rest, focus 세 가지 사용 맥락에서 VR,CdS 값을 수집해 vr_cds_dataset.json으로 저장한다. 이 파일을 replx get으로 PC로 옮기면 scikit-learn으로 더 체계적인 분류기를 학습할 수 있고, 그대로 다음 소절의 스마트 조명 프로토타입에 바로 활용할 수도 있다.

```python
# vr_cds_collect.py
from ulab import numpy as np
from ticle_lite.ain import Ain
from ticle_lite.button import Button
import json
import time

ain = Ain([27, 28])  # VR: GP27, CdS: GP28
btn = Button([16])   # UP button

SAMPLES = 10
INTERVAL = 100   # 100ms마다 한 번씩 읽기

def wait_button():
    while True:
        for _idx, event in btn.update():
            if event == "click":
                return
        time.sleep_ms(20)

def collect_context(label):
    print(f"모드 {label!r}: 버튼을 누르면 수집 시작")
    samples = []
    for i in range(SAMPLES):
        wait_button()
        print(f"  {i+1}/{SAMPLES} 수집 중... (5초)")
        vr_vals = []
        cds_vals = []
        for _ in range(50):  # 100ms × 50 = 5초
            vr = ain.read_percent()      # VR
            cds = ain.read_percent(idx=1) # CdS
            vr_vals.append(vr)
            cds_vals.append(cds)
            time.sleep_ms(100)
        # 특징: 평균값만으로도 충분
        feat = [float(np.mean(vr_vals)), float(np.mean(cds_vals))]
        samples.append(feat)
        print(f"  완료: VR={feat[0]:.1f}, CdS={feat[1]:.1f}")
    return samples

dataset = {}
for mode in ["night", "rest", "focus"]:
    dataset[mode] = collect_context(mode)

with open("vr_cds_dataset.json", "w") as f:
    json.dump(dataset, f)
print("저장 완료: vr_cds_dataset.json")

ain.deinit()
btn.deinit()
```

**코드 해설**

collect_context()에서 click 이벤트를 기다리는 이유는 imu_collect.py에서 press를 쓴 것과 다르다. IMU 수집은 버튼을 누르는 순간부터 동작이 시작되어야 했지만, VR,CdS는 먼저 VR 손잡이 위치와 조명 환경을 맞춰 두는 것이 더 중요하다. click(누르고 뗌)을 기다리면 사용자가 준비를 마치고 손을 뗀 시점에 수집이 시작되므로, 아직 값을 세팅하는 중에 수집이 시작될 가능성이 줄어든다.

50번 × 100ms = 5초 동안 읽어서 평균을 내는 이유는 두 가지다. 5초는 VR 손잡이를 안정적으로 잡고 있을 수 있는 현실적인 길이다. 동시에 CdS는 형광등 점멸이나 그림자에 의해 순간적으로 흔들리므로, 평균을 내면 이 잡음이 줄어든다.

특징을 평균 하나만 쓰는 이유는 이 센서들의 목적이 순간 변화가 아니라 현재 상태를 표현하기 때문이다. 표준편차를 추가하면 4차원이 되지만, VR,CdS의 표준편차는 수집 품질 차이를 반영할 뿐 동작 분류 정확도에 기여가 낮다. 2차원을 유지하면 PC에서 scatter plot으로 클래스 분리를 시각적으로 바로 확인할 수 있다는 이점도 있다.

**실행 결과와 확인할 점**

night 모드는 VR을 낮게, CdS도 낮게 두고, focus 모드는 VR을 높게, CdS도 높게 두고, rest 모드는 중간 정도로 설정해 3가지 모드를 수집한다. 생성된 vr_cds_dataset.json을 확인해 각 모드의 특징이 충분히 구분되는지 보자.

> **한 걸음 더**
> PC에서 이 데이터를 읽어서 dataset["night"], dataset["rest"], dataset["focus"] 각각의 평균점(무게중심)을 계산하고, 새로운 입력이 들어왔을 때 어느 점에 가장 가까운지 비교하는 간단한 분류기를 만들어 보자.

### 프로토타입: 대표점 비교로 즉시 분류하기

> **이 예제로 풀 문제**
> 사용자가 밝게 하고 싶은 정도와 실제 주변 밝기를 함께 고려하는 조명을 만들고 싶다. VR과 CdS를 함께 읽으면 더 똑똑한 조명이 될 수 있을까?

VR은 사용자의 의도를 나타내는 연속 입력이고, CdS는 주변 환경을 나타내는 맥락 입력이다. 둘을 함께 쓰면 사용자가 얼마나 밝게 원하는지와 지금 공간이 얼마나 어두운지를 한 번에 고려할 수 있다.

```python
# vr_cds_context_lamp.py
from ulab import numpy as np
from ticle_lite.ain import Ain
from ticle_lite.ws2812 import Matrix
from ticle_lite.lcd_hd44780 import HD44780 as TextLCD
import time

ain = Ain([27, 28])
mat = Matrix([0], brightness=0.15)

try:
    lcd = TextLCD(sda=12, scl=13, addr=0x27, cols=16, rows=2)
except Exception:
    lcd = None

PROTOTYPES = [
    (np.array([15.0, 10.0]), "night"),
    (np.array([45.0, 45.0]), "rest"),
    (np.array([80.0, 70.0]), "focus"),
]

COLOR = {
    "night": (0, 0, 40),
    "rest": (120, 60, 0),
    "focus": (180, 180, 180),
}

def predict(vr, cds):
    x = np.array([vr, cds])
    best_label = "rest"
    best_dist = 1e9
    for center, label in PROTOTYPES:
        d = np.sqrt(np.sum((x - center) * (x - center)))
        if d < best_dist:
            best_dist = d
            best_label = label
    return best_label

try:
    while True:
        vr = ain.read_percent()
        cds = ain.read_percent(idx=1)
        mode = predict(vr, cds)

        mat.fill(COLOR[mode])
        mat.update()

        if lcd:
            lcd.clear()
            lcd.text(mode, 0, 0)
            lcd.text("V:{:4.1f} C:{:4.1f}".format(vr, cds), 0, 1)

        print("mode:", mode, "vr:", vr, "cds:", cds)
        time.sleep_ms(300)
finally:
    if lcd:
        lcd.deinit()
    ain.deinit()
    mat.deinit()
```

**코드 해설**

predict()는 PROTOTYPES 리스트를 순회하면서 각 대표점과의 유클리드 거리를 직접 계산한다. 학습 데이터 전체를 저장하지 않고 대표점 세 개만 하드코딩하므로 메모리를 거의 쓰지 않고 즉시 실행할 수 있다. 이 방식은 데이터가 없어도 동작한다는 점에서 빠른 프로토타입에 적합하다.

VR과 CdS 값을 한 벡터로 묶으면 같은 VR 위치에서도 주변 밝기에 따라 다른 모드를 선택할 수 있다. 예를 들어 VR이 80이라도 CdS가 낮다면 night에 더 가깝고, CdS도 높다면 focus에 가깝다. 단일 입력 하나로는 이 맥락 구분이 불가능하다.

PROTOTYPES의 수치 값은 특정 환경의 대표점이므로, 다른 공간에서 사용하면 모드가 맞지 않을 수 있다. 이때는 보드에서 VR과 CdS를 직접 읽어 그 환경에서 실측한 값으로 PROTOTYPES를 갱신하면 바로 맞출 수 있다.

**실행 결과와 확인할 점**

VR을 돌리거나 CdS를 가리면 LCD와 Matrix 모드가 바뀌어야 한다. 같은 VR 위치에서도 밝은 환경과 어두운 환경에서 모드가 다르게 나오는지 확인한다.

> **한 걸음 더**
> 실제 환경에서 대표점 값이 맞지 않으면 vr_cds_collect.py로 데이터를 수집하고, replx get으로 PC에 옮긴 뒤, 다음 소절의 RF 배포 버전으로 교체해 보자. 교실, 침실, 창가처럼 조명 환경이 크게 달라지는 곳에서는 학습된 모델이 프로토타입보다 훨씬 안정적이다.

### PC에서 RF 학습

> **이 예제로 풀 문제**
> vr_cds_collect.py로 모은 데이터를 PC에서 Random Forest로 학습하고, emlearn_trees가 읽을 수 있는 CSV 모델 파일로 내보내려면 어떻게 해야 할까?

emlearn_trees는 결정 트리의 분기 임계값을 정수로 저장한다. 따라서 학습 단계에서 float 특징을 정수 스케일로 변환해야 한다. 같은 SCALE 값을 학습과 추론 양쪽에서 사용해야 분기 임계값과 입력값의 단위가 맞는다.

```python
# pc_train_vr_cds_rf.py
import json
import numpy as np
from sklearn.ensemble import RandomForestClassifier
from sklearn.preprocessing import LabelEncoder
import emlearn

SCALE = 100  # float feature * SCALE -> int16; must match board-side

with open("vr_cds_dataset.json") as f:
    raw = json.load(f)

labels_sorted = sorted(raw.keys())
le = LabelEncoder()
le.fit(labels_sorted)

X, y_str = [], []
for label, samples in raw.items():
    for feat in samples:
        X.append(feat)
        y_str.append(label)

# Scale to int16 before training: emlearn_trees stores thresholds as integers
X = (np.array(X, dtype=float) * SCALE).astype(np.int16)
y = le.transform(y_str)

clf = RandomForestClassifier(n_estimators=10, max_depth=5, random_state=42)
clf.fit(X, y)

# Export model for emlearn_trees (CSV format)
cmodel = emlearn.convert(clf)
cmodel.save(name='vr_cds_rf', format='csv', file='vr_cds_rf.trees.csv')

# Save label and scale metadata for board
meta = {
    'classes': {cls: int(i) for i, cls in enumerate(le.classes_)},
    'scale': SCALE,
    'n_trees': clf.n_estimators,
    'n_classes': int(len(le.classes_)),
}
with open('vr_cds_rf.meta.json', 'w') as f:
    json.dump(meta, f)

print(f"Saved. classes={list(le.classes_)}, features={X.shape[1]}")
```

**코드 해설**

SCALE = 100을 곱해 float 특징을 int16으로 변환한 뒤 학습하는 이유는 emlearn_trees가 결정 트리의 분기 임계값을 정수로 저장하기 때문이다. float 그대로 학습하면 emlearn.convert()가 임계값을 int로 잘라내면서 정밀도가 떨어진다. SCALE = 100은 VR 평균(0.0~1.0)을 0~100으로 변환해 int16 범위(±32767)에 여유 있게 들어간다. 보드에서도 같은 SCALE을 곱해 입력을 변환해야 트리 분기 조건과 입력값의 단위가 일치한다.

RandomForestClassifier의 n_estimators=10, max_depth=5는 보드 메모리를 고려한 값이다. 트리가 많을수록 성능은 높아지지만 CSV 파일 크기와 보드 로드 시간이 함께 늘어난다. max_depth가 깊어질수록 한 번 추론에 더 많은 분기를 탐색한다. TiCLE Lite에서 안정적으로 동작하는 조합을 실험으로 확인해야 한다.

emlearn.convert(clf)는 PC에서만 실행한다. 이 함수가 sklearn 트리 구조를 emlearn_trees가 읽을 수 있는 CSV 형식으로 변환한다. 메타 파일에 scale과 n_classes를 함께 저장하는 이유는 보드 쪽 코드에 같은 값을 하드코딩하지 않기 위해서다. meta.json 한 곳만 수정하면 PC와 보드 양쪽이 자동으로 동기화된다.

**실행 결과와 확인할 점**

vr_cds_rf.trees.csv와 vr_cds_rf.meta.json이 생성되어야 한다. 클래스 수 3, 특징 수 2가 출력되는지 확인한다. 데이터가 충분하면 sklearn의 classification_report로 교차 검증 f1-score가 0.8 이상인지 점검한다. f1-score가 낮은 클래스가 있으면 해당 클래스 데이터를 더 수집한다.

### 보드에서 RF 배포

> **이 예제로 풀 문제**
> 보드에서 vr_cds_rf.trees.csv를 로드하고, 실시간으로 VR+CdS 특징을 만들어 조명 모드를 분류하려면 어떻게 해야 할까?

```python
# vr_cds_rf_deploy.py
import json
import array
import time
import emlearn_trees
from ulab import numpy as np
from ticle_lite.ain import AIN
from ticle_lite.ws2812 import Matrix

# Load label and scale metadata
with open('vr_cds_rf.meta.json') as f:
    meta = json.load(f)

SCALE    = meta['scale']
N_TREES  = meta['n_trees']
N_CLASSES = meta['n_classes']
class_to_idx = meta['classes']
idx_to_class = {v: k for k, v in class_to_idx.items()}

# Load tree model; second arg = max nodes per tree (conservative upper bound)
model = emlearn_trees.new(N_TREES, 1000, N_CLASSES)
with open('vr_cds_rf.trees.csv') as f:
    emlearn_trees.load_model(model, f)

ain = AIN()
mat = Matrix([0], brightness=0.2)

SAMPLES  = 50
INTERVAL = 100  # ms

COLOR = {
    "night": (0,   0,  60),
    "focus": (60,  60,  0),
    "rest":  (0,  60,   0),
}


def argmax(arr):
    best_i, best_v = 0, arr[0]
    for i in range(1, len(arr)):
        if arr[i] > best_v:
            best_v, best_i = arr[i], i
    return best_i


def collect_and_predict():
    vr_buf, cds_buf = [], []
    for _ in range(SAMPLES):
        vr_buf.append(ain.read(0))
        cds_buf.append(ain.read(1))
        time.sleep_ms(INTERVAL)
    feat = [float(np.mean(np.array(vr_buf))),
            float(np.mean(np.array(cds_buf)))]
    q   = array.array('h', [int(v * SCALE) for v in feat])  # int16, same scale as training
    out = array.array('f', [0.0] * N_CLASSES)
    model.predict(q, out)
    return idx_to_class[argmax(out)]


print("RF deploy ready.")
try:
    while True:
        label = collect_and_predict()
        mat.fill(COLOR.get(label, (20, 20, 20)))
        mat.update()
        print("predict:", label)
        time.sleep_ms(200)
except KeyboardInterrupt:
    pass
finally:
    mat.fill((0, 0, 0))
    mat.update()
    mat.deinit()
    ain.deinit()
```

**코드 해설**

emlearn_trees.new(N_TREES, 1000, N_CLASSES)의 두 번째 인자 1000은 트리당 최대 노드 수를 나타내는 버퍼 크기다. max_depth=5일 때 트리 하나의 최대 노드 수는 2⁶−1=63이므로 10개 트리는 약 630노드가 된다. 1000은 넉넉한 상한값이며, 실제 노드 수가 이보다 적으면 나머지 공간은 사용되지 않는다.

model.predict(q, out)은 클래스별 투표 비율을 out 배열에 float로 채운다. argmax(out)으로 가장 높은 값의 인덱스를 찾아 클래스 이름으로 변환한다. 이 방식은 kNN과 달리 클래스별 신뢰도를 수치로 확인할 수 있다는 장점이 있다. out[i]가 0.7을 넘을 때만 레이블을 적용하는 방식으로 신뢰도 임계값을 추가하는 확장도 가능하다.

q를 array.array('h', ...)로 만드는 이유는 emlearn_trees가 int16 입력을 요구하기 때문이다. SCALE 값은 meta.json에서 읽어 오므로 PC 학습 시 SCALE이 바뀌어도 보드 코드를 수정할 필요가 없다.

**실행 결과와 확인할 점**

vr_cds_rf.trees.csv와 vr_cds_rf.meta.json을 replx put으로 보드에 복사한 뒤 실행한다. VR 손잡이를 최소로 놓고 주변이 어두운 상태에서 night, VR을 중간으로 놓고 밝은 환경에서 focus, VR을 최소로 놓고 밝은 환경에서 rest가 출력되는지 확인한다. 경계 근처 값에서 프로토타입 버전보다 분류가 더 안정적인지도 비교해 본다.

> **한 걸음 더**
> n_estimators를 5, 10, 20으로 바꾸어 학습하고 보드에서 응답 속도와 정확도가 어떻게 달라지는지 측정한다. max_depth를 3으로 줄이면 모델 파일이 작아지고 추론이 빨라지지만 경계 정확도가 낮아질 수 있다. 같은 워크플로를 초음파나 마이크 데이터에 적용하면 더 다양한 환경에서 안정적인 분류기를 만들 수 있다.

## 초음파: 손짓으로 조작하는 비접촉 버튼

> **풀고 싶은 문제**
> 버튼을 누르지 않고 손을 가까이 가져가거나 멈추거나 멀리 치우는 동작만으로 장치를 조작할 수 있을까?

초음파 센서는 단일 거리값만 읽는 장치처럼 보이지만, 시간 창으로 모으면 손짓 패턴이 된다. 이 절에서는 보드에서 손짓 데이터를 수집하고, 대표점 세 개로 즉시 분류하는 프로토타입을 확인한 뒤, PC에서 Random Forest를 학습해 보드에 배포하는 전 과정을 진행한다.

### 데이터 수집

> **이 예제로 풀 문제**
> approach, hold, leave 세 손짓 패턴을 수집하려면 어떤 특징을 추출하고 어떤 형식으로 저장해야 할까?

초음파 손짓 분류에서 유효한 특징은 세 가지다. 평균 거리는 손이 센서에서 얼마나 떨어져 있는지를 나타낸다. 최솟값은 가장 가까이 접근한 거리로 approach와 hold를 구분하는 단서가 된다. 창의 끝값에서 시작값을 뺀 변화량은 이동 방향을 나타내며, 가까워지면 음수, 멀어지면 양수, 유지되면 0에 가깝다. 아래 예제는 이 세 특징을 추출해 ultra_dataset.json으로 저장한다.

```python
# ultra_collect.py
from ulab import numpy as np
from ticle_lite.us import SR04 as UltraSonic
from ticle_lite.button import Button
import json
import math
import time

sonic = UltraSonic(trig=12, echo=13, median=5)
btn   = Button([16])  # UP button

WINDOW   = 12
INTERVAL = 50    # 50ms per sample -> 600ms per window
SAMPLES  = 10    # 10 samples per class

def wait_button():
    while True:
        for _idx, event in btn.update():
            if event == "click":
                return
        time.sleep_ms(20)

def get_feature():
    seq = []
    while len(seq) < WINDOW:
        d = sonic.read()
        if not math.isnan(d):
            seq.append(d)
        time.sleep_ms(INTERVAL)
    arr = np.array(seq)
    return [float(np.mean(arr)), float(np.min(arr)), float(arr[-1] - arr[0])]

def collect_class(label):
    print(f"Class {label!r}: Press button when ready")
    samples = []
    for i in range(SAMPLES):
        wait_button()
        print(f"  {i+1}/{SAMPLES} Collecting... (perform the gesture now)")
        feat = get_feature()
        samples.append(feat)
        print(f"  Done. mean={feat[0]:.3f} min={feat[1]:.3f} delta={feat[2]:.3f}")
    return samples

dataset = {}
for cls in ["approach", "hold", "leave"]:
    dataset[cls] = collect_class(cls)

with open("ultra_dataset.json", "w") as f:
    json.dump(dataset, f)
print("Saved: ultra_dataset.json")

sonic.deinit()
btn.deinit()
```

**코드 해설**

get_feature()에서 math.isnan(d) 체크가 필요한 이유는 초음파가 측정 범위 밖이거나 반사면이 없을 때 NaN을 반환하기 때문이다. NaN을 배열에 그대로 넣으면 np.mean이나 np.min도 NaN이 되어 특징이 깨진다. while 루프로 유효한 값이 WINDOW개 채워질 때까지 기다리는 방식은 손이 없는 상태를 자연스럽게 건너뛰어 준다.

세 클래스의 수집 방법은 다음과 같이 고정한다. approach는 버튼을 누른 뒤 센서 앞으로 손을 빠르게 가져가는 동작을 수행한다. hold는 손을 센서 앞 약 15~20cm 위치에 고정한 채로 유지한다. leave는 센서 앞에서 손을 빠르게 멀리 치운다. 수집 중 같은 방식으로 일관되게 반복해야 분류기가 안정적으로 학습된다.

**실행 결과와 확인할 점**

수집이 끝나면 ultra_dataset.json이 생성되어야 한다. 각 클래스의 delta 값을 확인한다. approach는 음수, hold는 0 근처, leave는 양수 값이 일관되게 나오면 수집이 잘 된 것이다. 값이 뒤섞여 있으면 손짓 속도나 방향을 더 일관되게 해서 다시 수집한다.

### 프로토타입: 대표점 비교로 즉시 분류하기

> **이 예제로 풀 문제**
> 버튼을 누르지 않고 손을 가까이 가져가거나 멈추거나 멀리 치우는 동작만으로 장치를 조작할 수 있을까?

초음파 센서는 단일 거리값만 읽는 장치처럼 보이지만, 시간 창으로 모으면 손짓 패턴이 된다. 아래 예제는 평균 거리, 최솟값, 시작과 끝의 차이를 이용해 approach, hold, leave를 분류한다.

```python
# ultra_air_button.py
from ulab import numpy as np
from ticle_lite.us import SR04 as UltraSonic
from ticle_lite.ws2812 import Matrix
from ticle_lite.audio import Audio
import math
import time

sonic = UltraSonic(trig=12, echo=13, median=5)
audio = Audio(sck=4, ws=5, sd_out=7, sd_in=6)
mat = Matrix([0], brightness=0.12)

WINDOW = 12
INTERVAL = 50

PROTOTYPES = [
    (np.array([0.25, 0.12, -0.20]), "approach"),
    (np.array([0.18, 0.15, 0.00]), "hold"),
    (np.array([0.30, 0.18, 0.18]), "leave"),
]

COLOR = {
    "approach": (0, 0, 120),
    "hold": (0, 120, 0),
    "leave": (120, 40, 0),
}

def predict(feat):
    x = np.array(feat)
    best_label = "hold"
    best_dist = 1e9
    for center, label in PROTOTYPES:
        d = np.sqrt(np.sum((x - center) * (x - center)))
        if d < best_dist:
            best_dist = d
            best_label = label
    return best_label

def get_feature():
    seq = []
    while len(seq) < WINDOW:
        d = sonic.read()
        if not math.isnan(d):
            seq.append(d)
        time.sleep_ms(INTERVAL)
    arr = np.array(seq)
    return [float(np.mean(arr)), float(np.min(arr)), float(arr[-1] - arr[0])]

try:
    while True:
        feat = get_feature()
        label = predict(feat)
        mat.fill(COLOR[label])
        mat.update()

        if label == "approach":
            audio.tone(660, 60)
        elif label == "hold":
            audio.tone(880, 80)
        else:
            audio.tone(440, 60)

        print("label:", label, "feature:", feat)
finally:
    sonic.deinit()
    mat.deinit()
    audio.deinit()
```

**코드 해설**

get_feature()에서 math.isnan(d) 체크가 필요한 이유는 초음파가 측정 범위 밖이거나 반사면이 없을 때 NaN을 반환하기 때문이다. NaN을 배열에 그대로 넣으면 np.mean이나 np.min도 NaN이 되어 분류가 실패한다. while 루프로 유효한 값이 WINDOW개 채워질 때까지 기다리는 방식은 손이 없는 상태를 자연스럽게 건너뛰어 준다.

특징 세 가지를 선택한 근거가 있다. 평균 거리는 손이 센서에서 얼마나 떨어져 있는지를 나타내고, 최솟값은 가장 가까이 접근한 거리를 나타내므로 approach와 hold를 구분하는 단서가 된다. arr[-1] - arr[0]은 창의 끝값에서 시작값을 뺀 변화량으로 이동 방향을 나타낸다. 가까워지면 음수, 멀어지면 양수, 유지되면 0에 가깝다.

predict()는 앞 소절의 스마트 조명과 같은 최근접 프로토타입 구조다. 센서가 달라도 분류기 뼈대는 같다. 달라지는 것은 특징 개수(여기서는 3차원)와 PROTOTYPES에 들어가는 수치 값뿐이다.

**실행 결과와 확인할 점**

센서 앞에서 손을 가까이 가져가면 approach, 잠시 머무르면 hold, 멀리 치우면 leave로 반응하는지 확인한다. 색과 음높이가 함께 달라져야 한다.

> **한 걸음 더**
> hold가 2회 연속 감지될 때만 확정하는 후처리를 추가해 잡음에 의한 잘못된 탐지를 줄여 보자. 비접촉 UI가 더 안정적이 된다. PC 학습까지 확장한다면 다음 소절의 RF 배포 버전으로 교체해 환경이 달라져도 안정적인 분류기를 유지할 수 있다.

### PC에서 RF 학습

> **이 예제로 풀 문제**
> ultra_collect.py로 모은 초음파 손짓 데이터를 PC에서 Random Forest로 학습하고, emlearn_trees가 읽을 수 있는 CSV 모델 파일로 내보내려면 어떻게 해야 할까?

초음파 거리값은 미터 단위 실수이므로, 보통 0.05~3.0m 범위에서 동작한다. 1000을 곱해 밀리미터로 변환하면 50~3000 범위의 정수가 되어 int16 범위(±32767) 안에 여유 있게 들어간다. 이 SCALE 값은 PC 학습과 보드 배포 양쪽에서 동일하게 사용해야 한다.

```python
# pc_train_ultra_rf.py
import json
import numpy as np
from sklearn.ensemble import RandomForestClassifier
from sklearn.preprocessing import LabelEncoder
import emlearn

SCALE = 1000  # meters -> millimeters (0.0~3.0 m -> 0~3000); must match board-side

with open("ultra_dataset.json") as f:
    raw = json.load(f)

labels_sorted = sorted(raw.keys())
le = LabelEncoder()
le.fit(labels_sorted)

X, y_str = [], []
for label, samples in raw.items():
    for feat in samples:
        X.append(feat)
        y_str.append(label)

X = (np.array(X, dtype=float) * SCALE).astype(np.int16)
y = le.transform(y_str)

clf = RandomForestClassifier(n_estimators=10, max_depth=5, random_state=42)
clf.fit(X, y)

cmodel = emlearn.convert(clf)
cmodel.save(name='ultra_rf', format='csv', file='ultra_rf.trees.csv')

meta = {
    'classes': {cls: int(i) for i, cls in enumerate(le.classes_)},
    'scale': SCALE,
    'n_trees': clf.n_estimators,
    'n_classes': int(len(le.classes_)),
}
with open('ultra_rf.meta.json', 'w') as f:
    json.dump(meta, f)

print(f"Saved. classes={list(le.classes_)}, features={X.shape[1]}")
```

**코드 해설**

SCALE = 1000을 곱하는 이유는 초음파 거리값이 0.05~3.0m의 소수 범위에서 동작하기 때문이다. 이 값을 그대로 int16으로 변환하면 0 또는 1 등 소수점 이하가 버려져 모든 샘플이 같은 값으로 뭉개진다. 1000배를 곱하면 50~3000mm로 변환되어 클래스 간 차이가 정수 단계에서도 충분히 유지된다. 변화량(arr[-1] - arr[0])은 음수가 될 수 있으나 int16은 음수도 표현하므로 문제없다.

학습 과정은 VR/CdS RF 학습과 동일한 구조다. LabelEncoder로 클래스 이름을 정수로 변환하고, RandomForestClassifier로 학습한 뒤 emlearn.convert()로 CSV 형식으로 내보낸다. 메타 파일에 scale, n_trees, n_classes, classes를 저장해 보드 배포 코드가 하드코딩 없이 동작하게 한다.

**실행 결과와 확인할 점**

ultra_rf.trees.csv와 ultra_rf.meta.json이 생성되어야 한다. 클래스 수 3, 특징 수 3이 출력되는지 확인한다. f1-score가 낮은 클래스가 있으면 해당 손짓을 더 일관되게 수집하고 다시 학습한다.

### 보드에서 RF 배포

> **이 예제로 풀 문제**
> 보드에서 ultra_rf.trees.csv를 로드하고, 실시간으로 초음파 특징을 만들어 손짓을 분류하려면 어떻게 해야 할까?

학습된 모델과 메타 파일을 보드에 복사한 뒤 실행하면, 별도의 수집이나 학습 없이 즉시 손짓 분류가 시작된다. 보드 코드는 VR/CdS RF 배포와 동일한 emlearn_trees 구조를 사용한다.

```python
# ultra_rf_deploy.py
import json
import array
import math
import time
import emlearn_trees
from ulab import numpy as np
from ticle_lite.us import SR04 as UltraSonic
from ticle_lite.ws2812 import Matrix
from ticle_lite.audio import Audio

with open('ultra_rf.meta.json') as f:
    meta = json.load(f)

SCALE     = meta['scale']
N_TREES   = meta['n_trees']
N_CLASSES = meta['n_classes']
idx_to_class = {v: k for k, v in meta['classes'].items()}

model = emlearn_trees.new(N_TREES, 1000, N_CLASSES)
with open('ultra_rf.trees.csv') as f:
    emlearn_trees.load_model(model, f)

sonic = UltraSonic(trig=12, echo=13, median=5)
audio = Audio(sck=4, ws=5, sd_out=7, sd_in=6)
mat   = Matrix([0], brightness=0.12)

WINDOW   = 12
INTERVAL = 50

COLOR = {
    "approach": (0,   0, 120),
    "hold":     (0, 120,   0),
    "leave":    (120, 40,  0),
}


def argmax(arr):
    best_i, best_v = 0, arr[0]
    for i in range(1, len(arr)):
        if arr[i] > best_v:
            best_v, best_i = arr[i], i
    return best_i


def collect_and_predict():
    seq = []
    while len(seq) < WINDOW:
        d = sonic.read()
        if not math.isnan(d):
            seq.append(d)
        time.sleep_ms(INTERVAL)
    arr  = np.array(seq)
    feat = [float(np.mean(arr)), float(np.min(arr)), float(arr[-1] - arr[0])]
    q    = array.array('h', [int(v * SCALE) for v in feat])  # int16, same scale as training
    out  = array.array('f', [0.0] * N_CLASSES)
    model.predict(q, out)
    return idx_to_class[argmax(out)], feat


print("Ultra RF deploy ready.")
try:
    while True:
        label, feat = collect_and_predict()
        mat.fill(COLOR.get(label, (20, 20, 20)))
        mat.update()
        if label == "approach":
            audio.tone(660, 60)
        elif label == "hold":
            audio.tone(880, 80)
        else:
            audio.tone(440, 60)
        print("label:", label, "feat:", feat)
finally:
    sonic.deinit()
    mat.deinit()
    audio.deinit()
```

**코드 해설**

collect_and_predict()는 수집과 추론을 하나의 함수로 묶는다. get_feature()로 특징을 추출하고 즉시 q로 변환해 모델에 넘기므로 중간 버퍼가 필요 없다. SCALE은 meta.json에서 읽어 오므로 PC 학습 시 SCALE이 바뀌어도 보드 코드를 수정할 필요가 없다. 이 패턴은 VR/CdS RF 배포와 동일하며 센서가 달라도 구조가 그대로 재사용된다.

idx_to_class = {v: k for k, v in meta['classes'].items()}는 정수 인덱스를 클래스 이름으로 역변환하는 딕셔너리다. model.predict(q, out) 후 argmax(out)으로 가장 높은 투표 비율의 인덱스를 구하고, 이를 클래스 이름으로 변환한다.

**실행 결과와 확인할 점**

ultra_rf.trees.csv와 ultra_rf.meta.json을 replx put으로 보드에 복사한 뒤 실행한다. 손을 가까이 가져가면 approach, 앞에서 유지하면 hold, 멀리 치우면 leave가 출력되는지 확인한다. 프로토타입 버전과 비교했을 때 같은 손짓에서 분류가 더 일관되게 나오는지도 비교해 본다.

> **한 걸음 더**
> 같은 워크플로에서 중앙값, NaN 비율, 변화 속도(표준편차) 등 특징을 추가하고 PC에서 다시 학습하면 approach와 leave의 경계가 더 정밀해진다. 보드에서 신뢰도(out 배열의 최대값)가 0.7 이상일 때만 반응하는 임계값 조건도 추가해 보자.

### 보드에서 추론: 반응형 미니 펫

> **이 예제로 풀 문제**
> 흔들기, 기울기, 정지 같은 IMU 분류 결과를 단순한 레이블이 아니라 감정 반응이나 자세 교정 피드백으로 바꿀 수 있을까?

gesture_model.json으로 만든 분류 결과는 그대로 두고 출력 매핑만 바꾸면, 보드는 작은 반응형 펫이나 자세 코치 장치가 된다. 같은 shake라도 어떤 프로젝트에서는 위험 신호이고, 다른 프로젝트에서는 즐거운 반응이 될 수 있다. 분류 로직은 재사용하고 경험 번역만 바꾸면, 코드 대부분을 유지하면서 전혀 다른 제품을 만들 수 있다.

```python
# imu_pet_companion.py
from ulab import numpy as np
from ticle_lite.audio import Audio
from ticle_lite.ws2812 import Matrix
from ticle_lite.servo import Servo
from ticle_lite.mpu6050 import MPU6050 as IMU
import json
import time

imu   = IMU(sda=12, scl=13, mode=IMU.Mode.RAW_FAST, coord="flu", remap="x-zy")
audio = Audio(sck=4, ws=5, sd_out=7, sd_in=6)
mat   = Matrix([0], brightness=0.15)
srv   = Servo(1, mode="positional", home_angle=90)

WINDOW   = 30
INTERVAL = 20

# Load PC-trained model exported by pc_train_knn.py
with open("gesture_model.json") as f:
    model = json.load(f)

mean     = np.array(model["mean"])
scale    = np.array(model["scale"])
X_train  = np.array(model["X_train"])
y_train  = model["y_train"]
k        = int(model["k"])


def get_feature():
    window = []
    for _ in range(WINDOW):
        ax, ay, az = imu.accel
        gx, gy, gz = imu.gyro
        window.append([ax, ay, az, gx, gy, gz])
        time.sleep_ms(INTERVAL)
    arr = np.array(window)
    return np.array(list(np.mean(arr, axis=0)) + list(np.std(arr, axis=0)))


def predict(feat):
    q    = (feat - mean) / scale
    diff = X_train - q
    dist = np.sqrt(np.sum(diff * diff, axis=1))
    idx  = list(range(len(dist)))
    idx.sort(key=lambda i: dist[i])
    votes = {}
    for i in idx[:k]:
        label = y_train[i]
        votes[label] = votes.get(label, 0) + 1
    return max(votes, key=votes.get)


def react(label):
    if label == "still":
        mat.fill((0, 60, 0))
        srv[0].move_to(90, ms=300)
        audio.note(['C5', 8])
    elif label == "shake":
        mat.fill((100, 30, 0))
        srv[0].move_to(140, ms=150)
        audio.note(['G5', 8, 'A5', 8])
    else:
        mat.fill((0, 0, 100))
        srv[0].move_to(50, ms=200)
        audio.note(['E5', 8])
    mat.update()

try:
    while True:
        label = predict(get_feature())
        react(label)
        print("pet reaction:", label)
        time.sleep_ms(100)
finally:
    mat.deinit()
    audio.deinit()
    srv.deinit()
    imu.deinit()
```

**코드 해설**

predict()가 gesture_model.json을 로드해 직접 구현한 이유는 9장의 gesture_deploy.py와 동일하다. 보드에서 PC와 동일한 StandardScaler 수식을 재현하기 위해 q = (feat - mean) / scale 변환을 먼저 수행하고, 정규화된 X_train 전체와 유클리드 거리를 계산한다. 이 정규화 단계가 없으면 가속도(m/s²)와 자이로(deg/s)의 스케일 차이가 거리 계산을 왜곡한다.

react()가 label 값을 if-elif로 직접 처리하는 이유가 있다. 색, 음, 서보 세 가지 출력이 레이블마다 서로 다른 패턴으로 연결되어 있어 딕셔너리 조회만으로는 표현하기 어렵다. 출력이 하나라면 딕셔너리가 낫고, 출력이 여러 종류이면서 각각 다른 처리가 필요하다면 if-elif가 더 읽기 쉽다.

IMU는 장착 방향에 민감하므로, 보드를 다른 방향으로 쥐면 coord와 remap 파라미터를 다시 맞춰야 한다. 분류가 불안정하면 coord, remap, WINDOW, INTERVAL 순서로 점검하는 것이 좋다.

**실행 결과와 확인할 점**

보드를 가만히 두거나 흔들거나 기울였을 때 색상, 음, 서보 움직임이 서로 다른 반응으로 바뀌어야 한다. 사용자는 이 반응을 통해 시스템이 단순 측정기가 아니라 상태를 해석하고 응답하는 장치로 느끼게 된다.

> **한 걸음 더**
> still, shake, tilt 외에 turn이나 drop 같은 새 클래스를 추가해 펫의 반응 어휘를 확장해 본다. imu_collect.py에서 해당 클래스를 추가 수집하고 pc_train_knn.py를 다시 실행해 gesture_model.json을 교체하면 된다.

## 디지털 마이크: 응원 반응기와 조용함 감시기

> **풀고 싶은 문제**
> 말소리, 박수, 조용함을 구분해 분위기에 반응하는 장치를 만들고 싶다. RMS 통계만으로 재미있는 응용이 가능할까?

디지털 마이크 입력은 파형 전체를 다루기보다 짧은 RMS 창의 평균, 최댓값, 표준편차를 이용하면 훨씬 간단하게 분류할 수 있다. 이 절에서는 보드에서 RMS 특징을 수집하고, 대표점 세 개로 즉시 분류하는 프로토타입을 확인한 뒤, PC에서 Random Forest를 학습해 보드에 배포하는 전 과정을 진행한다.

### 데이터 수집

> **이 예제로 풀 문제**
> quiet, voice, clap 세 가지 음향 환경을 수집하려면 어떤 특징을 추출하고 어떤 형식으로 저장해야 할까?

마이크 RMS 특징은 세 가지를 사용한다. 평균 RMS는 전반적인 음량 수준을 나타낸다. 최대 RMS는 창 안에서 순간 피크가 있었는지를 나타내므로 박수처럼 순간 충격이 강한 소리를 구분하는 단서가 된다. 표준편차는 음량이 얼마나 들쭉날쭉했는지를 나타낸다. 아래 예제는 이 세 특징을 추출해 mic_dataset.json으로 저장한다.

```python
# mic_collect.py
from ulab import numpy as np
from ticle_lite.audio import Audio
from ticle_lite.button import Button
import json
import time

audio = Audio(sck=4, ws=5, sd_out=7, sd_in=6, rate=16000)
btn   = Button([16])  # UP button

SAMPLES = 10

def wait_button():
    while True:
        for _idx, event in btn.update():
            if event == "click":
                return
        time.sleep_ms(20)

def get_feature():
    seq = []
    for _ in range(30):
        seq.append(audio.rms(160))
        time.sleep_ms(10)
    arr = np.array(seq)
    return [float(np.mean(arr)), float(np.max(arr)), float(np.std(arr))]

def collect_class(label):
    print(f"Class {label!r}: Set up the environment, then press button")
    samples = []
    for i in range(SAMPLES):
        wait_button()
        print(f"  {i+1}/{SAMPLES} Collecting...")
        feat = get_feature()
        samples.append(feat)
        print(f"  Done. mean={feat[0]:.1f} max={feat[1]:.1f} std={feat[2]:.1f}")
    return samples

dataset = {}
for cls in ["quiet", "voice", "clap"]:
    dataset[cls] = collect_class(cls)

with open("mic_dataset.json", "w") as f:
    json.dump(dataset, f)
print("Saved: mic_dataset.json")

audio.deinit()
btn.deinit()
```

**코드 해설**

wait_button()이 click 이벤트를 기다리는 이유는 사용자가 음향 환경을 먼저 만들어 두어야 하기 때문이다. quiet는 조용한 상태를 유지하면서 버튼을 누르고, voice는 말하기 시작하면서 버튼을 누르고, clap은 박수 직전에 버튼을 눌러야 수집 순간에 맞는 환경이 포착된다.

get_feature()가 평균, 최대, 표준편차 세 가지를 뽑는 이유가 있다. quiet는 세 값이 모두 낮고, voice는 평균과 표준편차가 중간 수준으로 유지된다. clap은 순간 피크가 매우 크므로 최대와 표준편차가 크게 나와 voice와 구분된다. 평균 하나만 쓰면 큰 목소리와 박수를 구분하기 어렵다.

**실행 결과와 확인할 점**

수집이 끝나면 mic_dataset.json이 생성되어야 한다. 각 클래스의 max 값을 비교한다. clap의 max가 voice의 max보다 확연히 크고, quiet의 max가 가장 낮다면 수집이 잘 된 것이다. 값이 비슷하면 clap을 더 세게 치거나 quiet를 더 조용한 환경에서 수집한다.

### 프로토타입: 대표점 비교로 즉시 분류하기

> **이 예제로 풀 문제**
> 말소리, 박수, 조용함을 구분해 분위기에 반응하는 장치를 만들고 싶다. 파형 전체를 이해하지 못해도 RMS 통계만으로 재미있는 응용이 가능할까?

디지털 마이크 입력은 파형 자체를 모두 다루기보다, 짧은 RMS 창의 평균, 최댓값, 표준편차를 이용하면 훨씬 간단하게 분류할 수 있다.

```python
# mic_reaction.py
from ulab import numpy as np
from ticle_lite.audio import Audio
from ticle_lite.ws2812 import Matrix
from ticle_lite.lcd_hd44780 import HD44780 as TextLCD
import time

audio = Audio(sck=4, ws=5, sd_out=7, sd_in=6, rate=16000)
mat = Matrix([0], brightness=0.12)

try:
    lcd = TextLCD(sda=12, scl=13, addr=0x27, cols=16, rows=2)
except Exception:
    lcd = None

PROTOTYPES = [
    (np.array([200.0, 400.0, 80.0]), "quiet"),
    (np.array([1200.0, 2400.0, 500.0]), "voice"),
    (np.array([1800.0, 7000.0, 2200.0]), "clap"),
]

COLOR = {
    "quiet": (0, 40, 100),
    "voice": (0, 120, 0),
    "clap": (120, 0, 120),
}

def predict(feat):
    x = np.array(feat)
    best_label = "quiet"
    best_dist = 1e18
    for center, label in PROTOTYPES:
        d = np.sqrt(np.sum((x - center) * (x - center)))
        if d < best_dist:
            best_dist = d
            best_label = label
    return best_label

def get_feature():
    seq = []
    for _ in range(30):
        seq.append(audio.rms(160))
        time.sleep_ms(10)
    arr = np.array(seq)
    return [float(np.mean(arr)), float(np.max(arr)), float(np.std(arr))]

try:
    while True:
        feat = get_feature()
        label = predict(feat)
        mat.fill(COLOR[label])
        mat.update()

        if lcd:
            lcd.clear()
            lcd.text("Mic:{}".format(label), 0, 0)
            lcd.text("mx:{:4.0f}".format(feat[1]), 0, 1)

        print("mic:", label, feat)
finally:
    if lcd:
        lcd.deinit()
    audio.deinit()
    mat.deinit()
```

**코드 해설**

get_feature()가 평균, 최대, 표준편차 세 가지를 뽑는 이유가 있다. 평균 RMS는 전반적인 음량 수준을 나타내고, 최대 RMS는 창 안에서 순간 피크가 있었는지를 나타낸다. 표준편차는 음량이 얼마나 들쭉날쭉했는지를 나타낸다. quiet는 세 값이 모두 낮고, voice는 평균과 표준편차가 중간 수준으로 유지된다. clap은 순간 피크가 매우 크므로 최대와 표준편차가 크게 나와 voice와 구분된다. 평균 하나만 쓰면 큰 목소리와 박수를 구분하기 어렵다.

PROTOTYPES의 수치 값은 특정 공간의 대표점이므로, 다른 환경에서는 quiet의 평균 RMS부터 다시 측정해 직접 갱신해야 한다. 조용한 교실과 시끄러운 복도에서 quiet의 배경 소음이 크게 다를 수 있기 때문이다.

I2S 마이크와 I2S 스피커는 같은 버스를 공유하므로, 분류 루프 안에서 audio.tone()을 자주 넣으면 RX/TX 전환 때문에 감지 공백이 생긴다. 소리 피드백이 꼭 필요하다면 클래스가 바뀐 직후 한 번만 짧게 재생하고 나머지는 색과 텍스트로 대체하는 편이 안정적이다.

**실행 결과와 확인할 점**

조용한 상태에서는 quiet, 보통 말소리에는 voice, 박수나 책상 두드림에는 clap으로 반응하는지 확인한다. 교실, 도서관, 공연장처럼 환경을 바꾸어 보고 프로토타입 값을 다시 조정해 본다.

> **한 걸음 더**
> quiet가 10초 이상 계속되면 집중 모드, clap가 연속 감지되면 응원 모드 애니메이션을 실행하도록 확장해 본다. 다음 소절의 RF 배포 버전으로 교체하면 공간이 달라져도 안정적인 분류기를 유지할 수 있다.

### PC에서 RF 학습

> **이 예제로 풀 문제**
> mic_collect.py로 모은 마이크 RMS 특징 데이터를 PC에서 Random Forest로 학습하고, emlearn_trees가 읽을 수 있는 CSV 모델 파일로 내보내려면 어떻게 해야 할까?

마이크 RMS 값은 0~7000 범위의 정수에 가깝다. 이 범위는 int16(±32767) 안에 그대로 들어가므로 SCALE = 1로 그냥 정수 변환해도 충분하다. float -> int16 변환에서 소수점이 버려지는 정밀도 손실은 0~7000 범위에서는 무시할 수 있다.

```python
# pc_train_mic_rf.py
import json
import numpy as np
from sklearn.ensemble import RandomForestClassifier
from sklearn.preprocessing import LabelEncoder
import emlearn

SCALE = 1  # RMS values 0~7000 fit in int16 as-is; must match board-side

with open("mic_dataset.json") as f:
    raw = json.load(f)

labels_sorted = sorted(raw.keys())
le = LabelEncoder()
le.fit(labels_sorted)

X, y_str = [], []
for label, samples in raw.items():
    for feat in samples:
        X.append(feat)
        y_str.append(label)

X = (np.array(X, dtype=float) * SCALE).astype(np.int16)
y = le.transform(y_str)

clf = RandomForestClassifier(n_estimators=10, max_depth=5, random_state=42)
clf.fit(X, y)

cmodel = emlearn.convert(clf)
cmodel.save(name='mic_rf', format='csv', file='mic_rf_trees.csv')

meta = {
    'classes': {cls: int(i) for i, cls in enumerate(le.classes_)},
    'scale': SCALE,
    'n_trees': clf.n_estimators,
    'n_classes': int(len(le.classes_)),
}
with open('mic_rf_meta.json', 'w') as f:
    json.dump(meta, f)

print(f"Saved. classes={list(le.classes_)}, features={X.shape[1]}")
```

**코드 해설**

SCALE = 1인 이유는 마이크 RMS 특징이 이미 0~7000 수준의 정수에 가까운 값이기 때문이다. VR/CdS(SCALE=100)나 초음파(SCALE=1000)와 달리 소수점 확대가 필요 없다. 학습 구조는 VR/CdS, 초음파 RF 학습과 동일하다. LabelEncoder, RandomForestClassifier, emlearn.convert() 호출과 메타 파일 저장 방식이 모두 같아서, 센서가 달라도 같은 패턴을 그대로 재사용할 수 있다.

**실행 결과와 확인할 점**

mic_rf_trees.csv와 mic_rf_meta.json이 생성되어야 한다. 클래스 수 3, 특징 수 3이 출력되는지 확인한다. clap와 voice의 f1-score가 낮으면 clap를 더 세게 치거나 voice를 더 일관된 음량으로 다시 수집한다.

### 보드에서 RF 배포

> **이 예제로 풀 문제**
> 보드에서 mic_rf.trees.csv를 로드하고, 실시간으로 RMS 특징을 만들어 음향 환경을 분류하려면 어떻게 해야 할까?

학습된 모델과 메타 파일을 보드에 복사한 뒤 실행하면, 별도의 수집이나 학습 없이 즉시 마이크 분류가 시작된다. 보드 코드는 VR/CdS와 초음파 RF 배포와 동일한 emlearn_trees 구조를 사용한다.

```python
# mic_rf_deploy.py
import json
import array
import time
import emlearn_trees
from ulab import numpy as np
from ticle_lite.audio import Audio
from ticle_lite.ws2812 import Matrix
from ticle_lite.lcd_hd44780 import HD44780 as TextLCD

with open('mic_rf_meta.json') as f:
    meta = json.load(f)

SCALE     = meta['scale']
N_TREES   = meta['n_trees']
N_CLASSES = meta['n_classes']
idx_to_class = {v: k for k, v in meta['classes'].items()}

model = emlearn_trees.new(N_TREES, 1000, N_CLASSES)
with open('mic_rf_trees.csv') as f:
    emlearn_trees.load_model(model, f)

audio = Audio(sck=4, ws=5, sd_out=7, sd_in=6, rate=16000)
mat   = Matrix([0], brightness=0.12)

try:
    lcd = TextLCD(sda=12, scl=13, addr=0x27, cols=16, rows=2)
except Exception:
    lcd = None

COLOR = {
    "quiet": (0,  40, 100),
    "voice": (0, 120,   0),
    "clap":  (120, 0, 120),
}


def argmax(arr):
    best_i, best_v = 0, arr[0]
    for i in range(1, len(arr)):
        if arr[i] > best_v:
            best_v, best_i = arr[i], i
    return best_i


def collect_and_predict():
    seq = []
    for _ in range(30):
        seq.append(audio.rms(160))
        time.sleep_ms(10)
    arr  = np.array(seq)
    feat = [float(np.mean(arr)), float(np.max(arr)), float(np.std(arr))]
    q    = array.array('h', [int(v * SCALE) for v in feat])
    out  = array.array('f', [0.0] * N_CLASSES)
    model.predict(q, out)
    return idx_to_class[argmax(out)], feat


print("Mic RF deploy ready.")
try:
    while True:
        label, feat = collect_and_predict()
        mat.fill(COLOR.get(label, (20, 20, 20)))
        mat.update()
        if lcd:
            lcd.clear()
            lcd.text("Mic:{}".format(label), 0, 0)
            lcd.text("mx:{:4.0f}".format(feat[1]), 0, 1)
        print("mic:", label, "feat:", feat)
finally:
    if lcd:
        lcd.deinit()
    audio.deinit()
    mat.deinit()
```

**코드 해설**

collect_and_predict()는 수집과 추론을 하나의 함수로 묶는다. 30회 RMS 측정으로 get_feature()와 동일한 특징을 만들고 즉시 int16 배열로 변환해 모델에 넘긴다. SCALE을 meta.json에서 읽으므로 PC 학습 시 SCALE이 바뀌어도 보드 코드를 수정할 필요가 없다. 이 패턴은 VR/CdS, 초음파 RF 배포와 동일하며 센서가 달라도 구조가 그대로 재사용된다.

main 루프에서 audio.tone()을 부르지 않는 이유는 I2S 마이크와 스피커가 같은 버스를 공유하기 때문이다. 재생 도중 RX/TX 전환이 일어나면 수집 공백이 생겨 분류가 불안정해진다. 소리 피드백이 꼭 필요하다면 분류 결과가 바뀐 직후 한 번만 짧게 재생하고, 나머지는 색과 텍스트로 대체한다.

**실행 결과와 확인할 점**

mic_rf_trees.csv와 mic_rf_meta.json을 replx put으로 보드에 복사한 뒤 실행한다. 조용한 상태에서는 quiet, 보통 말소리에는 voice, 박수나 책상 두드림에는 clap가 출력되는지 확인한다. 프로토타입 버전과 비교해 배경 소음이 달라진 환경에서도 분류가 더 안정적인지 비교해 본다.

> **한 걸음 더**
> 같은 RF 배포 워크플로로 shout이나 whisper 같은 클래스를 추가하면 음량 세분화 반응기로 확장할 수 있다. 신뢰도(out 배열의 최대값)가 낮을 때는 unknown으로 처리해 잘못된 분류를 줄여 보자.

이 절의 네 센서 예제는 모두 보드에서 데이터 수집, PC에서 모델 학습, 보드에서 추론이라는 동일한 파이프라인을 따른다. 센서가 달라져도 collect -> pc_train -> deploy 세 파일의 구조와 SCALE 변수만 조정하면 같은 워크플로로 전혀 다른 경험을 만들 수 있다.

## 정리

이 장은 9장에서 만든 수집 -> PC 학습 -> 보드 배포 파이프라인을 VR/CdS, 초음파, IMU, 디지털 마이크라는 네 가지 센서 응용으로 확장했다. 센서가 달라도 collect -> pc_train -> deploy 세 파일의 구조는 동일하며, 특징 추출 방식과 SCALE 변수만 조정하면 전혀 다른 경험을 만들 수 있다.

프로토타입 버전은 대표점 몇 개만으로 즉시 동작을 확인하는 빠른 검증 도구다. 환경이 달라지거나 클래스 경계가 복잡해질 때는 Random Forest 배포 버전으로 전환하면 더 안정적인 분류기를 얻을 수 있다. 두 방식을 함께 익히면 빠른 프로토타이핑과 안정적인 배포 사이의 선택을 상황에 맞게 판단할 수 있게 된다.

| 절 | 핵심 학습 |
|---|---|
| VR, CdS: 스마트 조명 | 두 센서를 2차원 벡터로 묶어 의도와 환경을 함께 분류 |
| 초음파: 비접촉 버튼 | 거리 시계열에서 손짓 패턴 특징 추출과 분류 |
| IMU: 반응형 미니 펫 | 9장 모델 재사용, 새 출력 매핑으로 경험 확장 |
| 디지털 마이크: 응원 반응기 | RMS 통계 특징으로 음향 상태 분류 |

정리하면, 10장을 마친 학습자는 다음을 수행할 수 있어야 한다.

1. 새로운 센서와 응용에 9장의 파이프라인 구조를 스스로 적용할 수 있다.
2. 프로토타입과 RF 배포 모델의 차이를 이해하고 상황에 맞게 선택할 수 있다.
3. emlearn_trees를 사용해 PC 학습 모델을 보드에 배포하고 실시간 추론을 수행할 수 있다.
4. 분류 결과를 다양한 출력 장치와 결합해 완성된 피지컬 AI 경험을 설계할 수 있다.

### 스스로 점검하기

1. 대표점 비교 프로토타입과 Random Forest 배포 모델을 각각 언제 사용하는 것이 적합한지 데이터 양과 환경 변화 관점에서 비교하시오.
2. VR과 CdS를 2차원 특징 벡터로 결합했을 때, 두 센서를 따로 사용할 때보다 어떤 분류 경계를 더 잘 표현할 수 있는지 설명하시오.
3. 초음파 손짓 분류에서 평균 거리, 최솟값, 변화량 특징이 각각 어떤 손 움직임 정보를 담는지 서술하시오.
4. IMU 절에서 새로운 데이터를 수집하지 않고 9장에서 만든 모델을 그대로 재사용할 수 있는 이유를 설명하시오.
5. 디지털 마이크 입력에서 평균 RMS, 최댓값, 표준편차를 특징으로 선택하는 이유를 quiet, voice, clap 세 클래스 구분 관점에서 설명하시오.
6. emlearn_trees가 요구하는 int16 배열과 SCALE 변수의 역할을 설명하고, SCALE이 학습과 추론에서 일치해야 하는 이유를 서술하시오.
7. 같은 collect -> pc_train -> deploy 구조를 새로운 센서에 적용하려면 어떤 부분을 수정해야 하는지 단계별로 설명하시오.
